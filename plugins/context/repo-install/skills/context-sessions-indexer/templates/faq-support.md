# Answer the question

Use this outline for one question or a coherent group of related questions.
Repeat the answer sections when that helps lookup; it is not a form to fill.

## Section blueprint

```markdown
## <the question, phrased the way a reader would ask it>
- Answer: the direct answer, in one or two sentences
- Applies when: the version, platform, configuration or role that bounds it
- What to do: the action or check that follows, when one does
- Not covered: the adjacent question a reader would otherwise assume is answered
```

The answer comes first and is required. Everything else exists to stop a reader
from applying the answer where it does not hold. Give `Applies when` whenever the
discussion bounds the answer; qualify a missing boundary when it changes how a
reader can use the answer, not as a generic disclaimer. Omit `What to do` when no
action follows.

Group by the reader's task, not by the number or order of questions in a thread.
Related questions about the same task can share a page with searchable headings;
separate questions with independent scope or use. Preserve existing page
identities when updating.

A session answers questions through people talking, which means the strength of
an answer varies inside one thread. Someone asking, someone guessing and someone
confirming are three different things; the page carries only what was actually
settled, at the strength it was settled. If the thread ended with the question
still open, that is not a FAQ entry — say the question is unresolved, or leave the
source saved without a page. An answer that was corrected later in the same
discussion uses the correction, not the first reply.
