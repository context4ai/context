# Updates and composition

Start with existing article titles, descriptions and references. Read relevant
article bodies or source passages when that navigation is insufficient. A
correction belongs in the affected article; do not create a page merely to
announce an improvement. A new reader question may justify a new target.
Several authorized sources and skills may contribute to the same article.
There is no primary-skill ownership or extension-profile binding to retain.

Use the current stage's plan submission to propose targets or append revision
tasks. Preserve accepted articles; do not overwrite a successful task by
resubmitting different content. Once a revision is issued, use its supplied
base Markdown and reference table to edit only the necessary sections through
the current submission schema. Keep useful unaffected examples and limitations.

Write drafts and submission files in the designated Agent temporary directory.
Submit their paths through the current CLI action, not long shell arguments.
The coordinator may submit a finished subset. Child Agents work only when the
current host supports them and the issued directory permits that scheduling;
they do not concurrently mutate shared production state.

An accurate source with a misleading article needs an article revision. An
incorrect source needs the authorized source-import correction flow, not an
Indexer quietly rewriting evidence. A source change invalidates affected task
inputs; follow the CLI refresh action and preserve unrelated work.

CLI acceptance saves a candidate for this run; it is not publication. Review
rejection requires repair, not deletion of the article's responsibility.
Temporary plans, candidates and receipts need not survive clearing temporary
storage or changing machines. A new run starts from formal sources, confirmed
long-term requirements and formal articles.
